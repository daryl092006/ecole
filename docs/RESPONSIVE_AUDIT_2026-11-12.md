## Réparation du banc de test

Le premier lancement était incomplet : 61 écrans par largeur. La lecture du profil utilisait une simulation Auth sans les données attendues par le nouveau GET `/api/session/profile` ; la fixture fournit désormais une réponse de profil isolée, cohérente avec le compte de test. Le test de redirection des actualités attend maintenant le titre actuel « Articles du site ». Les erreurs ne sont pas ignorées : les assertions sur les erreurs API, le rendu React et les redirections restent actives.

Un serveur de production local propre est construit et lancé pour chaque campagne. Les données et API sont simulées ; les écritures sont refusées. Les anciennes captures sont préservées dans `tmp/screenshots/responsive-audit/`.

## Validation

- Audit avant : 5 tests réussis, 77 écrans par largeur.
- Audit après : 5 tests réussis, aucune anomalie détectée sur les 385 vues.
- `npx tsc --noEmit --incremental false` : réussi.
- `npm run lint` : réussi.
- Inspection visuelle des captures avant et après à 360 px.

## Périmètre et limites

Ce contrôle couvre les pages initiales du catalogue de routes, les débordements, certains textes coupés, le rendu React, les réponses API simulées et les redirections. Il ne valide pas tous les états interactifs des formulaires et tiroirs, les permissions avec des comptes réels, les envois Microsoft ni la logique métier complète. Aucune migration, donnée distante, publication GitHub ou mise en production pendant cette intervention.
